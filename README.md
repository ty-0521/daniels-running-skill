# daniels-running-skill

[![CI](https://github.com/ty-0521/daniels-running-skill/actions/workflows/ci.yml/badge.svg)](https://github.com/ty-0521/daniels-running-skill/actions/workflows/ci.yml)

把《丹尼尔斯经典跑步训练法（第3版）》里能算的东西做成了程序。

给一次比赛成绩，它算 VDOT 和五档训练配速；给周跑量，它算每种训练单次最多能跑多长；给一张周表，它逐条查合不合规，超了多少公里写清楚。所有数字都来自方程和书里写明的百分比，你可以自己跑一遍核对。

零第三方依赖，Python 3.10 以上。可以装成 skill 给 agent 用，也可以当命令行工具或 Python 库直接调。

它本身不是训练计划表，也不是聊天机器人。它是个计算器加规则检查器：agent 拿它算出配速、上限和合规结论，再用人话讲给你听。

第一次用，建议先看[跑者使用手册](docs/使用手册.md)，那篇只讲怎么开口问。

## 它能回答什么

| 你会问 | 它给什么 |
|---|---|
| 我 5 公里 20 分，各强度该跑多快？ | VDOT 49.81，E/M/T/I/R 五档配速，含每 400 米、每 200 米 |
| 一周 50 公里，长跑最多跑多远？ | 15.0 公里（周跑量 30%），T 是 5.0 公里（10%） |
| 这张周表有问题吗？ | 第几周、哪条规则、超了多少公里、超了百分之几 |
| 距比赛还有 22 周，能排多长的计划？ | 能排哪几种长度、各自从哪天开始、Q 日放周几 |
| 赛前两周该去掉什么？ | 逐周列出来：去跨步、去跑坡、长跑压到 90 分钟 |
| 在 2130 米高原，配速要不要调？ | 要，I/T/M 每 400 米加 4 秒，R 不调 |
| 跑步机 8% 坡度等于多少配速？ | 书里没有换算表，它直说没有，不给一个看着合理的数 |

同样的边界还有：按年龄、性别调整配速，体重和饮食方案。这些不是它忘了做，是书里没有可用数据。

## 安装

### 装成 skill（DSH）

macOS / Linux：

```bash
git clone https://github.com/ty-0521/daniels-running-skill.git \
  ~/.dsh/skills/daniels-running-skill
```

Windows 用目录联接（不必复制，改一处两边都变）：

```powershell
git clone https://github.com/ty-0521/daniels-running-skill.git D:\daniels-running-skill
New-Item -ItemType Junction -Path "$env:USERPROFILE\.dsh\skills\daniels-running-skill" `
  -Target "D:\daniels-running-skill"
```

装完新开一个对话就能用。它不是 pip 包，没有 `pyproject.toml`，`pip install` 装不上，交付形态就是「一个文件夹 + 一个启动器」。

### 当命令行 / 库用

克隆到任意目录，装好 Python 就行，不用装任何依赖：

```bash
git clone https://github.com/ty-0521/daniels-running-skill.git
cd daniels-running-skill

# 自检，必须输出 VDOT = 49.81
python daniels_cli.py vdot 5k 20:00
```

不是 49.81 就说明环境不对（Python 版本低于 3.10，或者没有执行权限），先解决环境再说。

### 接到别的 agent 上

只要那个 agent 能 clone 仓库、能执行 Python，就能用，不需要 DSH。把仓库给它，让它先读根目录的 `AGENTS.md`（给 agent 的行为规则）和 `SKILL.md`（完整用法），再补一句：

> 先跑 `python daniels_cli.py vdot 5k 20:00`，输出 49.81 再往下做。

纯聊天、跑不了 Python 的助手用不了这个。它读不到方程，只能手算，而手算正是这个项目里所有真实出错的来源。

## 实际用起来是什么样

### 例 1：有成绩，想知道配速

> 我 5 公里 20 分 00 秒，一周跑 50 公里，半马该按什么配速练？

它给：

- VDOT 49.81
- E 4:54–5:31 /公里（轻松跑，能边跑边说话）
- M 4:32 /公里（马拉松配速，比赛日要撑完 21 公里）
- T 4:16 /公里（门槛跑，舒适的艰苦，能撑 30 到 40 分钟）
- I 3:56 /公里（间歇，很艰苦，单回合 3 到 5 分钟）
- R 1:27 /400 米（重复跑，快而短，每组不超过 2 分钟）
- 50 公里周的单次上限：长跑 15.0、T 5.0、I 4.0、R 2.5 公里

E/M/T/I/R 是书里的五种训练强度，中文名第一次出现时它都会解释。想知道为什么 E 要跑这么慢，可以直接问。

### 例 2：手里有张表，让它挑错

> 帮我审一下这两周：都是 50 公里。第 1 周长跑 18 公里、T 6 公里；第 2 周长跑 15 公里、T 5 公里。

它会直接列出来：

```
不通过：2 周里有 2 项错误；在修掉之前不可以说「合规」「0 违规」
  [cap/error] 第 1 周：L 跑 18.0 km 超过上限 15.0 km（周跑量 50 km）
  [cap/error] 第 1 周：T 跑 6.0 km 超过上限 5.0 km（周跑量 50 km）
```

「合规」这两个字只有整表审计全过才会说。超了多少、卡在哪条规则上，都会写出来，方便你改。

### 例 3：快比赛了，这几周还练什么

> 12 周后周日比赛，赛前这几周怎么减？

它按周给动作：

```
第 9 周   距赛 3 周   去跨步
第 10 周  距赛 2 周   去跨步、去跑坡
第 11 周  距赛 1 周   去跨步、去跑坡、长跑不超过 90 分钟
第 12 周  比赛周      去跨步、去跑坡
```

### 例 4：问书里没有的东西

> 跑步机 8% 坡度相当于户外多少配速？

它答：书里的坡度换算表是图片，只有一个可读的数字，还原不成表。书里只留了一条定性说法：「坡度加 2% 补风阻」。具体换算它不做，也不猜。

### 例 5：什么都没给，只说要排计划

> 帮我排个半马计划。

它不会直接给你一张表，会先问：

1. 比赛是哪一天？（没日期就算不出还有几周）
2. 现在有没有疼痛、伤病、刚做过手术、怀孕或心血管问题？（有就先停，不给训练量）
3. 最近一次尽力跑的成绩，距离和时间？
4. 一周跑多少公里，最长一次多少，一周能跑几天？

一次只问一层，答完再往下。缺任何一项，配速和上限它都不出数。那些数全是成绩和周跑量的百分比，缺了就只能猜。

## 它有多准

VDOT 正反算误差不超过 0.21，配速误差不超过 1.5%（M 0.14%、T 0.72%、I 0.45%、R 1.43%）。这两个数字不是自我评价，是拿书里的表和附录反算出来的，机器可读的版本在 `daniels.manifest()` 的 `error_bounds` 里。

`pace_audit.py` 是独立写的第二套方程实现，和库里的实现互相对照，用来排除「同一个笔误写了两遍」。

632 项测试覆盖了 `daniels/` 96.9% 的语句（标准库 trace 统计）。没覆盖到的主要是参数写错时的报错分支。

书里有几处算术笔误和前后不一致，代码怎么处理的写在[书本勘误](docs/书本勘误.md)。

## 它不做什么

| 问什么 | 为什么不做 |
|---|---|
| VDOT 低于 20 或高于 85 | 书里没这个范围的数据，会直接报错 |
| 按年龄、性别调整配速 | 原书那两张表是图片，没有可用真值 |
| 跑步机坡度换算表 | 只有一个可读锚点，还原不出来 |
| 体重、饮食方案 | 不属于训练量问题 |
| 每 N 周减量一次 | 书里没有这个概念，只有赛前减量和赛后恢复 |
| 逐字照抄书本的周表 | 书里的计划表是位图，这里按规则生成，不保证逐字一致 |
| 带伤、术后、孕期、心血管问题 | 只回一句先看医生，不给任何跑量 |

## 命令行

```bash
# 配速
python daniels_cli.py vdot 5k 20:00            # VDOT = 49.81
python daniels_cli.py paces 49.8               # 五档配速
python daniels_cli.py paces 49.8 --altitude 2130

# 训练量
python daniels_cli.py cap 64 T --vdot 49.8     # 单次上限
python daniels_cli.py check --weekly 64 --vdot 49.8 L18 T9 I5

# 周期与减量
python daniels_cli.py plan 24
python daniels_cli.py taper --weeks 12 --race-week 12
python daniels_cli.py deload --base 35 --weeks 12 --race-week 12
python daniels_cli.py progression 35 35 35 28 35 35 43 --sessions 4

# 整表审计、日历、接诊
python daniels_cli.py audit plan.json
python daniels_cli.py calendar --race 2027-04-18
python daniels_cli.py intake --goal 21.1 --date 2027-03-21 --weekly 19

# 出处与解释
python daniels_cli.py cite D-T-02
python daniels_cli.py cite --search 长跑
python daniels_cli.py explain "定速节奏跑和巡航间歇的区别"
python daniels_cli.py topics
```

退出码只有三种，脚本可以据此分流：

| 码 | 含义 |
|---|---|
| 0 | 正常 |
| 1 | 参数不对、格式不对、算不出来；`intake` 还没问齐 |
| 2 | 跑完了，但发现了问题：超限、不合规、命中伤病红线 |

`audit` 读一个 JSON 文件（给 `-` 就从标准输入读）。格式：顶层写 `sessions_per_week` 和 `base_source`，`weeks` 里每周写 `week`、`weekly_km`、`sessions`（如 `[["L", 8], ["T", 4.8]]`），比赛周另加 `race_km`。

## 在代码里用

```python
import daniels as d

# 一次成绩 -> VDOT 和五档配速
vdot = d.vdot_from_race(5000, 20 * 60)      # 5 公里 20:00 -> 49.81
paces = d.pace_set(round(vdot, 2))
paces.t.seconds_per_km                      # 255.98 秒/公里，也就是 4:16

# 一周 50 公里的单次上限：周跑量 × 百分比
d.cap_for("L", 50).max_km                   # 15.0
d.cap_for("T", 50).max_km                   # 5.0

# 整张表的裁决：六类检查全过，passed 才是 True
weeks = [
    d.WeekEntry(week=i, weekly_km=50.0,
                sessions=(d.Session("L", 15.0), d.Session("T", 5.0)))
    for i in (1, 2)
]
result = d.audit_plan(weeks, sessions_per_week=4, base_source="user")
result.passed                               # True
print(result.report())                      # 通过：2 周，6 类检查全过
```

## 注意事项

### 它不是医疗器械，也不是教练

它不诊断、不建议治疗。出现疼痛、肿胀、打软腿、关节卡住、夜里静息痛，或者几天内加重，去看医生或运动康复。收到「膝盖疼」这类输入它会直接停下，不给跑量。这是刻意划的边界，不是保守。

它也不知道你今天睡了几小时、腿沉不沉、昨天有没有应酬。这些只有你知道。

### 它的错，长什么样

写这个项目的过程里跑过十几轮真实对话测试，错的形状很固定：

- 输入不齐就开口。用户只说「每次 35 分钟」，它自己折成 17 公里，后面全建在这个数上。
- 把假设说成事实。两轮之后又说「之前按 18 公里估的，这个数是对的」，可那是它自己估的。
- 拿单项校验冒充整表合规。只跑了加量节奏那一项，就说「12 周全部通过」，实际长跑超了上限 48%。
- 手算代替调用。20 周的起点算成周日，只有 141 天，装不满 20 周。

现在这些各有对应的机制挡着：接诊门禁、`base_source` 标记、整表审计、日期函数。机制不能保证它不犯错，只能保证错了你看得见。

### 你要怎么核对它

它给的每个数，只该有三个来源：

1. 你给的（成绩、周跑量、日期）
2. 函数算的（同一个函数你可以自己跑一遍）
3. 标着「假设」的（那它就不能当事实用）

看到不属于这三类的数字，就是它编的。这是你唯一需要的检查方法：

- 问它「这个数哪来的」，合格回答会给你章号行号、函数名，或者明说这是假设。
- 让它算 5 公里 20 分的 VDOT，答案必须是 49.81。
- 问它跑步机坡度怎么换算，正确答案是「书里没有」，如果它开始讲心率或配速，就是在硬凑。

## 还没做的事

- `explain` 是关键词匹配，不是语义检索。换个说法可能问不到，问不到时它会说没有。
- 周表只保证剂量合规、阶段正确，不保证和书本印的第 17 周课表逐字一致。
- 「连续两场比赛怎么排」「比赛周撞上质量课怎么办」还没有词条，现在会如实说没有。
- GitHub 的 Topics 还没填。

发现数字不对，把三样东西一起发上来最有用：你的输入、它给的数、你算的数（附章号行号）。`tests/` 里每条回归用例都注明了来自哪一轮真实测试，照那个格式加就行。
